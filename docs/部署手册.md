## 一、建GitHub 远程仓库

浏览器打开：**https://github.com/new**

逐项填写：

- **Owner**：选你的账号
- **Repository name**：`work-guide`（或 `gaoxiaojianbeidaoguan`）
- **Public** ✅选 Public
- ⚠️ 下面四个勾**全部不要勾**：
  - Add a README file
  - Add .gitignore
  - Choose a license
  - Allow GitHub to create an initial commit

> 这四项任意一个勾上，远程就有 commit 了，本地 push 会因为「历史分叉」被拒。
> 本地已经有完整历史，远程必须是**空仓库**。

点 **Create repository**。

## 二、推送代码

### 方式A：GitHub 网页新建时的引导命令

建完仓库后 GitHub 会显示一段命令，把 `YOUR_USERNAME` 换成你的用户名，
在项目目录里依次跑：

```bash
cd "C:/Users/lihuijun/WorkBuddy/2026-10-06-12-10-17/work-guide"
git remote add origin https://github.com/YOUR_USERNAME/work-guide.git
git push -u origin main
```

push 时会弹窗要求登录：用户名 + 密码。
**密码位置要填 Personal Access Token，不是 GitHub 密码**（GitHub 2021 年起已禁用密码推送）。

拿 Token：https://github.com/settings/tokens → Generate new token (classic)
- 勾 `repo`
- 有效期选 30 或 90 天
- 生成后立刻复制（只显示一次）

### 方式 B：用 SSH（一次配好，以后不用再输）

```bash
ssh-keygen -t ed25519 -C "your_email@example.com"
cat ~/.ssh/id_ed25519.pub          # 复制输出内容
```

把这段加到 https://github.com/settings/keys → New SSH key。
然后把远程地址换成 SSH：

```bash
git remote set-url origin git@github.com:YOUR_USERNAME/work-guide.git
git push -u origin main
```

### 推送成功的标志

```
branch 'main' set up to track 'origin/main'.
To https://github.com/YOUR_USERNAME/work-guide.git
 * [new branch]      main -> main
```

## 三、接 Cloudflare Pages

1. 打开 **https://dash.cloudflare.com** → 登录
2. 左侧 **Workers & Pages** → **Pages** 标签 → **Create application**
3. 选 **Connect to Git** → 授权 GitHub
4. 选仓库 `work-guide` → **Start setup**

### 关键配置（这几个字段必须对）

| 字段 | 填什么 |
|---|---|
| Project name | `work-guide`（决定默认域名 `work-guide.pages.dev`） |
| Production branch | `main` |
| **Build command** | `npx --yes node@20 && npm run build` |
| **Build output directory** | `dist` |
| Root directory | 留空 |

> **为什么 Build command 不是简单的 `npm run build`**
> Cloudflare 默认 Node 18跑，`vite 5` + `tsc` 在 18 上偶发报错。
> 前半段的 `npx --yes node@20` 强制用 Node 20 跑后面的命令。
> 如果你在项目设置里加了 `NODE_VERSION=20` 环境变量，
> 这里就可以直接填 `npm run build`。

5. 环境变量（可选但建议）：`NODE_VERSION` = `20`
6. 点 **Save and Deploy**

### 部署成功

约 1-2 分钟后拿到 `https://work-guide.pages.dev`。
之后每次 push 到 `main`，Cloudflare 自动重新构建部署——这就是「连了 GitHub」的价值。

## 四、自定义域名（想让 footer 指向主站时再买）

1. Cloudflare Pages 项目 → **Custom domains** → **Set up a custom domain**
2. 填你的域名（如 `guide.yourname.com`）
3. Cloudflare 自动加 CNAME 记录，HTTPS 证书自动签发，**几分钟生效**
4. 如果域名不在 Cloudflare 托管，需要你手工加一条 CNAME：
   `guide` → `work-guide.pages.dev`

改完再把 `src/config.ts` 里的 `AUTHOR_URL` 改成你的主站地址，push 一次即生效。

## 五、常见报错对照

| 报错 | 原因 | 解决 |
|---|---|---|
| `rejected ... non-fast-forward` | 远程仓库不是空的 | GitHub 建仓库时把 README 等四个勾去掉；或删远程重来的 |
| `remote origin already exists` | 已经配过 remote | 用 `git remote set-url origin <新地址>` |
| `Permission denied (publickey)` | 用了 SSH 但没加公钥 | 改用 HTTPS 方式 A，或先把公钥加到 GitHub |
| `remote: Support for password authentication removed` | 用了 GitHub 密码 | 换成 Personal Access Token |
| 构建日志报 `tsc` 找不到 | Node 版本不对 | 用上面给的 `npx --yes node@20 && npm run build` |
| 部署完打开是空白页 | 路由问题 | 本项目用 Hash Router（`#/chapter/ch03`），不会踩这个坑；若真出现，先看构建是否有 error |
| 部署成功但 404 | Output directory 填错 | 必须是 `dist`，不是 `build` |

## 六、以后的日常流程

```bash
# 改完代码
npm run validate      # 内容校验：出处、阈值线必须齐全
npm run build         # 本地先确认能构建
git add -A && git commit -m "描述"
git push              → Cloudflare 自动部署，约 1-5 分钟
```

**建议**：把 Cloudflare 的部署 URL 分享出去前，先本地 `npm run validate` 过一遍。
`validate` 会在缺出处、缺阈值线时直接失败——这是内容项目的护栏，比类型检查更重要。
