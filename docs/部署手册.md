# GitHub + Cloudflare Pages 部署手册

本地仓库已初始化（分支 `main`，已有首次提交）。剩下三步：建远程仓库 → 推送 → 接 Pages。

> **读者全在大陆，务必先看第七节。** Cloudflare 默认的 `pages.dev` 域名
> 在国内不稳定且可能遭 DNS 污染，分享给读者前必须换方案。

## 先定一件事：用哪个 GitHub 账号

如果你有两个账号（一个 Gmail 注册、一个 163 邮箱注册），**面向中国大陆读者的项目选 163 那个。**

理由不是偏好，是硬约束：

| 维度 | 163 账号 | Gmail 账号 |
|---|---|---|
| 邮箱可达性 | 国内直连 | **大陆不可访问** |
| Pages 部署成功/失败通知 | 直接收到 | 进黑洞，需另开转发 |
| 读者提 issue 时的邮件回复 | 通畅 | 你自己看不到 |
| 与读者语境一致 | 是 | 否 |

GitHub 的所有系统通知（部署成功、构建失败、issue、PR 评论）**只发到账号邮箱**。
选 Gmail 就等于把部署告警发到一个你收不到的信箱里——构建挂了要等访客发现。
Gmail 那个留着当备用号或私人项目即可。

**选定后必须同步改提交邮箱。** GitHub noreply 邮箱的前缀就是用户名：

```bash
# 把下面两行的 actual_username 换成你在 163 账号里的用户名
cd "C:/Users/lihuijun/WorkBuddy/2026-10-06-12-10-17/work-guide"
git config user.name "你的名字"
git config user.email "actual_username@users.noreply.github.com"
```

改完要**重写已有提交**才会生效，否则前两次提交不会关联到账号：

```bash
git rebase --exec 'git commit --amend --no-edit --reset-author' -i HEAD~2
git push -u origin main   # 若还没推送过，直接推即可
```

> 也可以在 GitHub 网页上直接改：Settings → Emails →
> Keep my email addresses private on → 记下它显示的 noreply 地址。
> 公开仓库**必须**用 noreply 邮箱，否则真实邮箱会暴露给所有访客。

## 一、建GitHub 远程仓库

浏览器打开：**https://github.com/new**

逐项填写：

- **Owner**：选你的账号
- **Repository name**：`work-guide`（或 `gaoxiaojianbeidaoguan`）
- **Public** ✅选 Public
- ⚠️ 下面四个勾**全部不要勾**：
  - Add a README file
  - Add .gitignore
  - Choose a license
  - Allow GitHub to create an initial commit

> 这四项任意一个勾上，远程就有 commit 了，本地 push 会因为「历史分叉」被拒。
> 本地已经有完整历史，远程必须是**空仓库**。

点 **Create repository**。

## 二、推送代码

### 方式A：GitHub 网页新建时的引导命令

建完仓库后 GitHub 会显示一段命令，把 `YOUR_USERNAME` 换成你的用户名，
在项目目录里依次跑：

```bash
cd "C:/Users/lihuijun/WorkBuddy/2026-10-06-12-10-17/work-guide"
git remote add origin https://github.com/YOUR_USERNAME/work-guide.git
git push -u origin main
```

push 时会弹窗要求登录：用户名 + 密码。
**密码位置要填 Personal Access Token，不是 GitHub 密码**（GitHub 2021 年起已禁用密码推送）。

拿 Token：https://github.com/settings/tokens → Generate new token (classic)
- 勾 `repo`
- 有效期选 30 或 90 天
- 生成后立刻复制（只显示一次）

### 方式 B：用 SSH（一次配好，以后不用再输）

```bash
ssh-keygen -t ed25519 -C "your_email@example.com"
cat ~/.ssh/id_ed25519.pub          # 复制输出内容
```

把这段加到 https://github.com/settings/keys → New SSH key。
然后把远程地址换成 SSH：

```bash
git remote set-url origin git@github.com:YOUR_USERNAME/work-guide.git
git push -u origin main
```

### 推送成功的标志

```
branch 'main' set up to track 'origin/main'.
To https://github.com/YOUR_USERNAME/work-guide.git
 * [new branch]      main -> main
```

## 三、接 Cloudflare Pages

1. 打开 **https://dash.cloudflare.com** → 登录
2. 左侧 **Workers & Pages** → **Pages** 标签 → **Create application**
3. 选 **Connect to Git** → 授权 GitHub
4. 选仓库 `work-guide` → **Start setup**

### 关键配置（这几个字段必须对）

| 字段 | 填什么 |
|---|---|
| Project name | `work-guide`（决定默认域名 `work-guide.pages.dev`） |
| Production branch | `main` |
| **Build command** | `npx --yes node@20 && npm run build` |
| **Build output directory** | `dist` |
| Root directory | 留空 |

> **为什么 Build command 不是简单的 `npm run build`**
> Cloudflare 默认 Node 18跑，`vite 5` + `tsc` 在 18 上偶发报错。
> 前半段的 `npx --yes node@20` 强制用 Node 20 跑后面的命令。
> 如果你在项目设置里加了 `NODE_VERSION=20` 环境变量，
> 这里就可以直接填 `npm run build`。

5. 环境变量（可选但建议）：`NODE_VERSION` = `20`
6. 点 **Save and Deploy**

### 部署成功

约 1-2 分钟后拿到 `https://work-guide.pages.dev`。
之后每次 push 到 `main`，Cloudflare 自动重新构建部署——这就是「连了 GitHub」的价值。

## 四、自定义域名（想让 footer 指向主站时再买）

1. Cloudflare Pages 项目 → **Custom domains** → **Set up a custom domain**
2. 填你的域名（如 `guide.yourname.com`）
3. Cloudflare 自动加 CNAME 记录，HTTPS 证书自动签发，**几分钟生效**
4. 如果域名不在 Cloudflare 托管，需要你手工加一条 CNAME：
   `guide` → `work-guide.pages.dev`

改完再把 `src/config.ts` 里的 `AUTHOR_URL` 改成你的主站地址，push 一次即生效。

## 五、常见报错对照

| 报错 | 原因 | 解决 |
|---|---|---|
| `rejected ... non-fast-forward` | 远程仓库不是空的 | GitHub 建仓库时把 README 等四个勾去掉；或删远程重来的 |
| `remote origin already exists` | 已经配过 remote | 用 `git remote set-url origin <新地址>` |
| `Permission denied (publickey)` | 用了 SSH 但没加公钥 | 改用 HTTPS 方式 A，或先把公钥加到 GitHub |
| `remote: Support for password authentication removed` | 用了 GitHub 密码 | 换成 Personal Access Token |
| 构建日志报 `tsc` 找不到 | Node 版本不对 | 用上面给的 `npx --yes node@20 && npm run build` |
| 部署完打开是空白页 | 路由问题 | 本项目用 Hash Router（`#/chapter/ch03`），不会踩这个坑；若真出现，先看构建是否有 error |
| 部署成功但 404 | Output directory 填错 | 必须是 `dist`，不是 `build` |

## 六、以后的日常流程

```bash
# 改完代码
npm run validate      # 内容校验：出处、阈值线必须齐全
npm run build         # 本地先确认能构建
git add -A && git commit -m "描述"
git push              → Cloudflare 自动部署，约 1-5 分钟
```

**建议**：把 Cloudflare 的部署 URL 分享出去前，先本地 `npm run validate` 过一遍。
`validate` 会在缺出处、缺阈值线时直接失败——这是内容项目的护栏，比类型检查更重要。

## 七、⚠️ 大陆访问：部署平台的选择

**这一节最重要。** 本站读者全部在中国大陆，托管平台选错，再好的内容也打不开。

### Cloudflare 默认域名的真实问题

Cloudflare **没有中国大陆节点**（大陆节点只对 Enterprise 开放），
`*.pages.dev` 这个二级域名在国内还常遭 DNS 污染。社区实测（截至 2026-08）：

- 有开发者实测 CNAME 指向 `pages.dev` 会解析到 `127.0.0.1`，归因 DNS poisoning
- 移动宽带最明显，部分运营商/时段能通——属于「不稳定」而非「完全不可用」
- 联通晚高峰 800ms+，波动大
- `workers.dev` 比 `pages.dev` 更差，别用

**结论：不要把 `xxx.pages.dev` 直接分享给读者。**

### 平台对比

| 平台 | 国内表现 | 备案 | 备注 |
|---|---|---|---|
| **腾讯 EdgeOne Pages** | 备案域名 50–90ms | 静态站免备案 | 腾讯生态，GitHub 自动部署，免费额度含10GB/月 流量 |
| Cloudflare Pages + 自有域名 | 绑定域名后可用，联通晚高峰仍慢 | 免 | 免费额度最慷慨（无限带宽、私有仓库也能部署） |
| Cloudflare Pages 默认 `pages.dev` | **不稳定，部分运营商直接解析失败** | 免 | 别用于分享 |
| GitHub Pages | 国内极慢 | 免 | 软性带宽限制 100GB/月 |
| Vercel | `vercel.app` 基本打不开 | 免 | 官方明确不面向大陆 |

### 建议路线

**分阶段，不要一步到位。**

**阶段一 · 验证期（现在）**
先上 Cloudflare Pages，用 `pages.dev` 域名即可。这个阶段访问者是自己和少量朋友，
流量小、可控，**不急着买域名**。你要验证的是内容框架站不站得住，不是访问速度。

**阶段二 · 分享给读者时**
两个选择，按预算和预期流量定：

- **预算为零** → 继续 Cloudflare Pages，但**必须绑自有域名**。
  域名层污染是针对 `pages.dev` 的，自有域名能绕开大部分问题。
  买域名约 ¥60-100/年。
- **想要国内速度和稳定性** → 迁到腾讯 EdgeOne Pages。国内 50–90ms，
  静态站免备案，GitHub 集成同样一键自动部署。迁移成本极低——
  因为构建产物就是同一个 `dist/`，改配置不用动业务代码。

**阶段三 · 内容做起来之后**
日活稳定再考虑 ICP 备案 + 国内 CDN。备案要 15–30 天，现在做太早。

### 无论选哪个都免备案

服务端节点不在中国大陆境内，ICP 备案的管辖范围到不了。
这与Vercel / Netlify / Cloudflare Pages / GitHub Pages 一样，
是国内个人开发者常规做法，完全合法。

## 八、缓存配置说明

`public/_headers` 只给 `/assets/*` 设了一年强缓存，
因为 Vite 产物文件名带内容 hash，内容变了文件名就变，缓存不会串。

**如果你换到别的平台**，这个文件不生效，需要在平台控制台配置等效规则。
EdgeOne Pages 的控制台有对应的「静态资源缓存」设置项。
