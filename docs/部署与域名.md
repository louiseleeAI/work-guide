# 部署与域名方案

## 一、先回答一个常见误解

**footer 里链向另一个站点，不等于需要两个域名。**

「域名数量」和「页面路径数量」是两件独立的事。同一套代码可以部署成：

| 方案 | 需要注册的域名数 | 访问形式 | footer 链接性质 |
|---|---|---|---|
| **A. 同域子路径** | 1 | `yoursite.com/guide` | 站内跳转 |
| **B. 独立域名** | 2 | `guide.yoursite.com` 或 `yoursite.net` | 跨站跳转 |

Ben 用的是方案 B：`howtolivebetter.net` 是独立域名，所以 footer 必须链回 `benx.ai`——
因为对访客而言这是两个不同的站。如果你把指南放在 `yoursite.com/guide`，
footer 链回主站时**不需要换域名，只是一条普通链接**。

---

## 二、两种方案的取舍

### 方案 A：同域子路径

```
https://yourname.com/          主站（你的个人主页 / 业务站）
https://yourname.com/guide/    高性价比打工指南
```

**优点**
- 只买一个域名，省 ¥60-100/年和 DNS 配置成本
- SEO 权重集中，指南给主站导流
- 不用管跨域、证书、CDN 分配置

**缺点**
- 指南的独立品牌感弱，URL 里带着你的主站
- 以后想把指南单独转让或独立运营，需要再拆一次

**适合**：验证阶段、内容规模还小、本来就只有一个主站。

### 方案 B：独立域名

```
https://yourname.com/          主站
https://yourguide.com/         指南（独立域名）
```

**优点**
- **品牌完全独立** —— `howtolivebetter.net` 这个名字不带任何个人色彩，
  看着像一个正经出版的内容站，而不是「某人网站的一个栏目」
- 可以单独转让、单独授权、单独运营
- 访客心理更信任：内容站的读者和业务站的受众互不干扰

**缺点**
- 额外域名成本 + DNS 配置
- SEO 权重分散，两个站各自从零积累
- 需要在两处分别部署（如果用同一份构建产物，其实只是一份）

**适合**：内容做到一定规模、想要独立品牌、或打算长期把它做成一个真正的产品。

---

## 三、我的建议

**现在用方案 A。** 理由：

1. 站点是纯静态的，**以后拆域名成本极低**——只是把同一份 `dist/` 部署到新域名，
   改一行 base 配置，不用改任何业务代码
2. 现在最重要的验证是「内容有没有人看、框架站不站得住」，不是品牌独立
3. 省下的钱和精力应该花在写内容上

**什么时候该拆？** 满足任一条就可以考虑：

- 指南日活稳定在可观量级，且和主站业务明显不是同一批人
- 有人问「这个指南能不能单独拿去做」
- 你想给这个内容一个不依赖个人姓名的名字
- 想接入统计、SEO、或者做独立的商业模式

## 四、代码怎么改

所有站点相关的配置集中在 **`src/config.ts`**，组件里不写死任何域名：

```ts
export const AUTHOR_NAME = 'Ben'
export const AUTHOR_URL = 'https://benx.ai/'
export const SHOW_BUILD_CREDIT = true
export const SITE_NAME = '高性价比打工指南'
export const UPDATED_AT = '2026-10-06'
```

`AUTHOR_URL` 支持两种写法：

- **站内路径**：`'/'` → 渲染成 `<a href="/">`，点击在站内跳转，不开新窗口
- **绝对地址**：`'https://benx.ai/'` → 渲染成 `target="_blank" rel="noreferrer"`，
  跨站跳转并加上安全属性

组件会自动判断写哪种，不用手动切换。

## 五、部署步骤

### 构建产物

```bash
npm run build     # 产物在 dist/，纯静态文件
```

### 本地预览

```bash
npm run preview   # 默认 4173 端口
```

### 部署选项

**方案 A：同域子路径**

1. `dist/` 部署到主站的 `/guide/` 路径下
2. 如果主站是静态托管，把 `dist/` 里的文件放到 `public/guide/` 目录
3. `vite.config.ts` 的 `base` 改成 `'./guide/'`（用相对路径更省事，
   这样 `dist/` 放到任何路径下都能正常工作，当前配置已经是相对路径）

**方案 B：独立域名**

1. 买域名
2. `dist/` 部署到静态托管（Vercel / Netlify / Cloudflare Pages / GitHub Pages 都行）
3. 在 DNS 里加 A 记录或 CNAME 指向托管平台
4. 平台配置里绑定自定义域名，签发 HTTPS 证书
5. `vite.config.ts` 的 `base` 保持 `'./'`（相对路径，部署到任何位置都不需要改）

**用相对路径的好处**：`base: './'` 让同一个 `dist/` 目录能放在
`example.com/guide/` 或 `cdn.example.com/app/guide/` 下都能跑，
换域名时一行配置都不用改。这是纯静态站的标准做法。

## 六、Cloudflare Pages 部署（推荐，纯静态最省事）

1. 推代码到 GitHub
2. Cloudflare Pages → Create project → 连仓库
3. Build command：`npm run build`
4. Output directory：`dist`
5. 部署后拿到 `xxx.pages.dev` 域名
6. 之后买独立域名，在 Pages 项目的 Custom domains 里加上去，证书自动签发
7. `src/config.ts` 里把 `AUTHOR_URL` 改成你的主站地址

全程零成本，静态站不需要服务器。
